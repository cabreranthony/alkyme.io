The replayability problem

Strategy games hit a replayability cliff: players learn the meta, then novelty fades. New maps and DLC treat symptoms while the core rules stay fixed.

ChronoCore asks what changes if the rules themselves become a session variable—still deterministic and debuggable, but meaningfully different each time.

Capabilities

Each session compiles a validated session genome—economy, combat, diplomacy, win paths, and manifests that stay mechanically coherent. Three layers you can adopt incrementally.

Use seed and constraints first, add behavior-tree assembly and sandboxed scripting when your team is ready.

  • Layer 1

    Procedural seed system and constraint resolution—modules with dependencies and exclusions resolve into a reproducible genome.

  • Layer 2

    Behavior tree generation from a node library—designers author nodes; the engine assembles valid trees per session.

  • Layer 3

    Sandboxed scripting API—session logic through a fixed, validated surface (designer scripts today; safe hooks for generated code later).

At a glance

  • Seed-stable

    The same 64-bit seed reproduces the same ruleset—built for QA, tournaments, and shareable runs.

  • Constraint-solved

    Genomes resolve from modules with dependencies and exclusions—not decor randomness on a static ruleset.

  • Incremental

    Ship with Layer 1, opt into behavior trees and scripting when production is ready for them.

Dominion Eternal

Dominion Eternal (internal codename EPOCH) is our reference game: tile-based grand strategy from antiquity through galactic eras, built to stress-test the engine in the browser. The MVP is deliberately text-forward—the engine is the product; graphics are additive.

Every session is shareable by seed so teams, players, and tournaments can replay identical rule configurations.
